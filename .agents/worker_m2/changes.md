## Harness Design Details
1. **CLI & Environment Configuration**:
   - `--concurrency` / `-c` / `CONCURRENCY` (default: 150)
   - `--duration` / `-d` / `DURATION` (default: 15 seconds)
   - `--url` / `-u` / `URL` / `TARGET_URL` (default: `http://localhost:5000`)

2. **Socket Pool Tuning**:
   - `http.Agent({ keepAlive: true, maxSockets: 1000, maxFreeSockets: 200, keepAliveMsecs: 1000 })`
   - `https.Agent({ keepAlive: true, maxSockets: 1000, maxFreeSockets: 200, keepAliveMsecs: 1000 })`

3. **User Lifecycle & Workflow Loops**:
   - `POST /api/auth/signup` (User registration with unique generated email)
   - `POST /api/auth/login` (User authentication & JWT token retrieval)
   - `GET /api/transactions` (Ledger read with user Bearer token)
   - `POST /api/transactions` (Ledger insert with user Bearer token)
   - `GET /api/admin/metrics` (Admin telemetry query with admin Bearer token)

4. **Telemetry & Metrics**:
   - Nanosecond timer precision via `process.hrtime.bigint()`.
   - Complete percentile calculations (`min`, `avg`, `max`, `p50`, `p90`, `p95`, `p99`).
   - Throughput calculations (requests/sec).
   - HTTP status code tracking (`2xx`, `4xx`, `5xx`, `networkErrors`).
   - Per-endpoint detailed telemetry breakdown.

5. **Reporting**:
   - Formatted visual console ASCII dashboard printed to stdout.
   - Machine-readable JSON telemetry exported to `stress_test_report.json`.

6. **Server Auto-Management**:
   - Automatically probes server health at startup. If server is unreachable, spawns an ephemeral `server.js` process and waits for health check before commencing benchmark, terminating spawned server on completion.
